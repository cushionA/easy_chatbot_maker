# 01. サービス概要

## 一言で

組織のナレッジマスタをアップロードすると、その組織専用のRAGチャットボットURLが払い出される、マルチテナント型SaaSプラットフォーム。

## 目的（座布団さんの観点）

転職ポートフォリオとしての**成長機会**と**実プロダクト感の実証**。Webエンジニアとしての設計力・実装力・コスト感覚を採用面接で語れる形にする。

## 既存 Streamlit 版との関係

既存 [`helpdesk_bot`](C:\Users\tatuk\Desktop\チャットボット\helpdesk_bot) を **PoC** として位置づけ、本格Web版として発展させる。職務経歴書では以下の流れで語る：

> 「Streamlit版でPoCを作成し、Embedding+LLMフォールバックという検索戦略の妥当性を検証した。本格Web版ではマルチテナント・認証・ハイブリッド検索・動的フォーム生成等を追加し、本物のSaaS設計に発展させた」

詳細：[10_existing_streamlit.md](10_existing_streamlit.md)

## 主要差別化軸

| # | 差別化軸 | 既存サービス（Dify/ChatBase/Mendable）との違い |
|---|---|---|
| 1 | **動的フォーム生成** | LLMがマスタから必要フィールドを推論、または管理者が型付き定義 |
| 2 | **3段階エスカレーション** | 自動回答 / 起票前ガイダンス / 直接起票 の3レベル |
| 3 | **複数起票先の抽象化** | Adapter パターンで Redmine / GitHub Issues / 将来追加可能 |
| 4 | **BYOK LLM 設計** | LLMを必須依存ではなく拡張として設計、$0運用基盤 |
| 5 | **ハイブリッド検索** | BM25 + Embedding (RRF) + match_count 重み |
| 6 | **埋め込みウィジェット** | `<script>` タグでテナントの自社サイトに常駐可能 |
| 7 | **未分類キュー＋ナレッジギャップ検出** | 失敗ケースをフィードバックループでマスタに反映 |

## 訴求先（採用領域別）

| 応募先 | 主訴求点 |
|---|---|
| **データ収集・検索基盤・AI 系** | TS/Node フルスタック、ハイブリッド検索（Elasticsearch）、RAG、E2E テスト、マルチテナント、データ基盤（BigQuery）|
| **汎用Web/SaaS** | プラットフォーム設計、Adapter パターン、共通モジュール、コスト感覚 |
| コミュニケーション / ソーシャル系 | Service B（Ronkaku）側の訴求が中心、本サービスは副 |
| ゲーム業界 | Service B 側の訴求が中心 |

## 主要機能（MVP）

詳細は [08_features.md](08_features.md)。

- 組織アカウント・認証（OIDC / JWT）
- マスタアップロード（Excel/JSON、Phase 2 で PDF）
- カテゴリ → コンボボックス → 自然言語の段階的分類
- BM25 + Embedding ハイブリッド検索
- 動的フォーム生成（複数項目フラグ対応）
- 自動回答 / ガイダンス / 起票の3段階エスカレーション
- Redmine / GitHub Issues 起票
- 引用元ハイライト
- 暗黙シグナルベースのフィードバック収集 + 自動回答後の「解決した」ボタン
- 未分類キュー（管理画面でレビュー）
- ナレッジギャップ検出（低確信度回答の可視化）
- 組織別ボットURL払い出し（`/t/{slug}/chat`）
- 埋め込みウィジェット（`embed.js`）
- 利用ログ・分析

## スコープ外（明示的に MVP に含めない）

- マルチターン対話の高度な文脈保持（直近3発言結合のみ）
- 音声入力・出力
- Slack/Teams 連携
- A/B プロンプトテスト
- ペルソナカスタマイズ
- PDF・Word の非構造文書取込（`document_chunks`）
- Re-ranker（クロスエンコーダ）
- Git からのマスタ同期
- PII 自動マスキング
