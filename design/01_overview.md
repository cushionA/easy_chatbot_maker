# 01. サービス概要（TrendScope）

## 一言で

開発系の Web 上の言及を **API 主軸 + クロール脇役**で収集し、技術用語の**トレンド（特に「新出・急上昇・廃れ」）を時系列で可視化・検知**する、マルチテナント型の技術トレンド観測プラットフォーム。コードネーム **TrendScope**。

> 「いま何の技術が立ち上がりつつあるか（次の MCP は何か）」を、スター数 API だけでなく**Web 上の"言及"そのもの**から捉える。

## 目的（座布団さんの観点）

入社が確定しポートフォリオ評価の縛りが外れたため、本サイトの目的を**転職アピール用の体裁**から、**入社後の実務に直結するスキルの実証・予習**へ振り直す。具体的には次を「全部主役」で扱う:

- **会社の技術スタック全振り**: TypeScript / Node.js / Docker / Kubernetes / BigQuery、マルチクラウド（AWS / GCP / Azure）。
- **機械学習モデルの活用**: 用語抽出（NER）・表記揺れ名寄せ・近重複除去・変化点/異常検知・要約。
- **クローリングの実務予習**: 礼儀正しいクローラ（robots 遵守・レート制御・条件付き GET・per-site アダプタ・構造変化検知）。ただし**主役は API、クロールは"公式 API が無い隙間"の脇役**。

UI の作り込みは優先しない（「クソサイトでも可」）。価値は**データ収集パイプライン・ML・データ基盤**の堅さに置く。

## 合法・コンプライアンス方針（設計の一級市民）

題材が「他者サイトの収集」である以上、合法ラインを引く判断力そのものを設計に組み込む。

- **API / フィード優先**、クロールは公式アクセスが無い対象に限定。
- 対象ごとに **robots.txt と利用規約を確認**。レート制御・指数バックオフ・連絡先入り User-Agent。
- **保存するのは派生データ（用語頻度・メタ・短い文脈スニペット・要約）のみ。本文全文は保持・再配布しない**（根拠の一つは著作権法 30 条の 4 = 情報解析目的の利用。ただし同条の但書・ToS・サーバ負荷は別軸で個別判断する。詳細は [07_data_strategy.md](07_data_strategy.md)）。
- 詳細は [04_security_multitenant.md](04_security_multitenant.md)・[07_data_strategy.md](07_data_strategy.md)。

## 主要機能（MVP）

詳細は [08_features.md](08_features.md)。

| # | 機能 | 概要 |
|---|---|---|
| **F1** | トレンド可視化 | 技術用語の出現を時系列で表示（BigQuery 集計） |
| **F2** | **ライフサイクル検知（核）** | **新出**（クロスソース裏取り）/ **急上昇**（シェア正規化 + z-score）/ **廃れ** |
| **F3** | 技術サマリ自動生成 | 用語ごとの LLM 要約（RAG）。末尾に**関連トピック**（embedding 近傍） |
| **F6** | エビデンス / ドリルダウン | 用語 → 時系列 + **出典記事リンク** + 関連語 + 例文（本文は保存せずリンク） |
| **F8** | 収集ヘルス | ソース別 鮮度 / 失敗率 + パーサ破損検知（スクレイピング運用の要） |
| **F9** | 用語辞書 / 正規化 | 別名マージ（k8s↔Kubernetes）・除外語・曖昧性解消（"Go"=言語か動詞か） |

**fast-follow**: F5 JP vs Global 比較（Qiita vs HN）/ F7 アラート・ダイジェスト配信 + ウォッチリスト / 急上昇クラスタの「ムーブメント検知」（次の MCP）。

## 主要差別化軸

| # | 差別化軸 | 内容 |
|---|---|---|
| 1 | **言及ベースのトレンド** | スター数等の集計値でなく、Web 上の"言及"を一次信号にする |
| 2 | **新出検知** | 「昨日までゼロ → 複数ソースでぽつぽつ」をクロスソース裏取りで捉える |
| 3 | **API 主軸 + クロール脇役** | 公式アクセスを優先し、隙間だけ礼儀正しくクロール（実務の正解形） |
| 4 | **3 層データ基盤** | Postgres（メタ）/ Elasticsearch（検索・エビデンス）/ BigQuery（時系列・検知） |
| 5 | **合法設計** | robots/ToS 遵守・派生データのみ保存をアーキに内蔵 |
| 6 | **収集ヘルスの可観測性** | パーサ破損・鮮度劣化を検知（黙ってデータが腐らない） |

## 訴求先（採用領域別）

| 領域 | 主訴求点 |
|---|---|
| **データ収集・検索基盤・AI 系** | クロール/取込パイプライン、検索基盤（ES）、ML 検知、BigQuery DWH、合法設計 |
| **汎用 Web / SaaS** | TS/Node フルスタック、マルチテナント、Adapter（Source）パターン、コスト感覚 |

## スコープ外（MVP に含めない）

- 規約でスクレイピングを禁止する対象（小説投稿サイト・pixiv・大手 SNS 等）の収集
- 固定タクソノミ（カテゴリ分類）＝ overkill のため**関連トピック軽量版**で代替
- リアルタイム（秒単位）収集 — 日次〜数時間バッチで十分
- 高度なパーソナライズ / 推薦
- 本文全文の保存・再配信

## 旧チャットボット設計からの流用

本サービスは、先行して設計していた RAG チャットボット（社内ナレッジ起票補助）から**横断インフラ（マルチテナント RLS / OIDC / Secret Manager / Elasticsearch / BigQuery / Docker・K8s / CI / テスト戦略 / BYOK）をそのまま流用**し、**ドメイン（チャットボット → クロール + トレンド検知）だけ差し替えた**もの。流用マッピングは [10_existing_streamlit.md](10_existing_streamlit.md)。
